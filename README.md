# 따릉이 순유출 예측 기반 선제 재배치 제안

2026-2 기계학습기초 팀 프로젝트 (5조)

## 1. 프로젝트 개요

서울 따릉이는 대여소 간 자전거 쏠림이 크지만 재배치 인력은 한정되어 있다.
이 프로젝트는 공개 대여이력으로 **대여소·시간 블록별 순유출(대여 건수 − 반납 건수)** 을 회귀로 예측하고,
곧 비거나 넘칠 대여소를 미리 찾아 순회 우선순위와 마일리지 대상 후보를 제안하는 것을 목표로 한다.

- 문제 유형: 지도학습, 회귀
- 비교 모델: 단순 기준선(지난주 같은 요일·블록 값), Ridge 회귀, Random Forest, LightGBM, MLP(가산점)
- 분할: 시간순 분할(학습 → 검증 → 테스트). 랜덤 분할은 미래 정보가 새어 들어가 사용하지 않는다.
- 평가 지표: RMSE, MAE, R²
- 활용 검증: 예측 순유출 상위 k개 대여소와 테스트 기간 실제 상위 k개의 일치율(Precision@k)

공개 데이터만 사용한다. 생년·성별·이용자종류 컬럼은 사용하지 않고 대여소 단위로 집계한다.

> 호출 시점의 보유 대수와 거치율은 예측에 사용하지 않는다.

## 4. 재현 방법

1. 패키지 설치
   ```bash
   pip install -r requirements.txt
   ```
2. 인증키 설정: 서울 열린데이터광장에서 인증키를 발급받고, `.env.example`을 복사해 `.env`로 만든 뒤 키를 입력한다.
3. 원본 데이터를 받아 `data/raw/`에 둔다. 파일 이름과 기간은 아래 표에 기록한다.

   | 파일 | 기간 | 비고 |
   |---|---|---|
   | (입력: 2025년 대여이력 중 7–12월분) | 2025.7–2025.12 | 연별 파일에서 해당 월만 사용 |
   | (입력: 2026년 월별 파일) | 2026.1–2026.6 | |

4. 아래 순서로 실행한다. (경로는 본인 컴퓨터에 맞게 바꾼다. 큰 데이터는 저장소 밖 폴더에 둔다.)
   ```bash
   python src/01_fetch_stations.py                                   # 대여소 정보(거치대 수, 위경도) 수집 -> data/reference/stations.csv
   python src/02_aggregate_months.py --data-dir C:/bike_data --out-dir C:/bike_data/processed
   python src/03_build_base_table.py --counts C:/bike_data/processed/counts_all.csv --out C:/bike_data/processed/base_table.csv
   python src/04_merge_stations.py --base C:/bike_data/processed/base_table.csv --out C:/bike_data/processed/table_stations.csv
   python src/05_merge_weather.py --table C:/bike_data/processed/table_stations.csv --weather C:/bike_data/<기상청_파일>.csv --out C:/bike_data/processed/table_final.csv
   python src/06_split_time.py --table C:/bike_data/processed/table_final.csv --out-dir C:/bike_data/processed
   ```
   - 05: 기상청 종관기상관측(ASOS) 서울(108) 시간자료를 시간 블록별로 집계(기온 평균, 강수량 합, 풍속 평균)해 결합한다. 강수량 빈 칸은 0으로 처리한다.
   - 06: 날짜 기준 시간순 분할(학습 70% / 검증 15% / 테스트 15%). 결과는 `train.csv`, `val.csv`, `test.csv`.

## 5. 데이터 처리 기준

- 시간 블록: 하루를 5개로 나눈다. 0=0–6시, 1=6–10시, 2=10–16시, 3=16–20시, 4=20–24시.
- 순유출: 대여소·날짜·블록별 (대여 건수 − 반납 건수). 대여는 대여 시각, 반납은 반납 시각 기준으로 센다.
- 제외 기준(정제)
  - 같은 대여소에서 반납했고 이동거리가 0m인 건, 반납 시각이 대여 시각보다 이른 건, 대여 정보가 빈 건은 제외한다.
  - 반납 대여소ID만 빈 건(2026년 파일에서 월 0.5–0.6%)은 버리지 않고 대여로만 센다. 반납은 대여소를 알 수 없어 세지 않는다.
  - 월별 제외 건수는 정제 로그(`cleaning_log.json`)에 저장된다.
- 빈 칸 처리: 각 대여소의 활동 기간 안에서 기록이 없는 날짜·블록은 0으로 채운다.
- 분석 구간: 2025-07-03 – 2026-06-30. 첫 이틀은 2025-06-30에 빌린 건의 반납이 파일에 없어 제외한다.
- 대여소 속성 결합: API 목록에 없는 대여소 99개(분석 기간 대여의 약 1.7%)는 위치·거치대 수를 알 수 없어 제외한다.
- 사용 기간: 2025.7–2026.6 (최근 12개월)
- 데이터 분할(날짜 기준, 363일): 학습 2025-07-03–2026-03-13(254일), 검증 2026-03-14–2026-05-06(54일), 테스트 2026-05-07–2026-06-30(55일). 무작위 분할은 미래 정보가 섞이므로 쓰지 않는다.
- 입력 피처 12개: block, weekday, month, is_holiday, temp_c, rain_mm, wind_ms, lat, lon, docks, net_prev_block, net_prev_day. 목표 변수는 net_out이며 대여·반납 건수는 입력에 쓰지 않는다.

## 7. 한계

- 공개 데이터에는 대여소별 재고가 없어, 순유출을 부족·과잉의 간접 지표로 사용한다.
- 관측된 대여 건수는 실제 수요와 다를 수 있다. 자전거가 없는 대여소의 수요는 기록되지 않는다.
- 2026년 파일에서 반납 대여소가 기록되지 않은 건(약 0.5%)은 반납으로 집계하지 못해 같은 기간 순유출이 약간 높게 잡힌다.
- 2026년 파일에는 같은 대여소에서 거리 0m로 빌렸다가 바로 반납한 취소성 기록이 2025년 파일보다 훨씬 많다(약 2–3% 대 0.2–0.4%). 순유출에서는 대부분 상쇄된다.
- 대여소 거치대 수·위경도는 API 호출 시점(2026-11)의 스냅샷이라 분석 기간의 값과 다를 수 있고, 그 사이 사라진 대여소는 제외된다.
- 데이터가 1년뿐이라 학습 구간에 봄이 없고, 테스트는 5–6월이다. 계절 차이로 테스트 성능이 낮아질 수 있고, 테스트 구간의 순유출 변동(표준편차 8.3)이 학습 구간(6.9)보다 크다.
- 기상은 서울 한 지점(ASOS 108) 값을 모든 대여소에 같이 적용한다. 강수량 빈 칸은 0으로 처리했으며, 겨울철 관측 간격에 따른 빈 칸 의미는 확인하지 못했다.
- 서울·한정된 기간의 데이터이므로 다른 계절과 다른 도시로의 일반화는 검증되지 않았다.
